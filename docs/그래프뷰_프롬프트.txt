이 저장소(UBDA 경영분석 — 산업 → 카테고리 → 기업을 3D 네트워크로 탐색하는 정적 사이트)의
3D 기업 네트워크 화면(index.html)을 "옵시디언 그래프 뷰" 느낌의 새 화면으로 바꿔줘.
지금 화면은 큰 색 구체가 떠 있는 방식인데, 새 화면은 어두운 배경 위에 작은 점(노드)과 가는 선으로 된
3D 지식 그래프야. 기업을 한 번 누르면 바로 그 기업 대시보드로 들어가야 해.
기업 목록은 화면 파일에 적지 말고 companies/index.json을 읽어서 그려줘 (데이터만 바꾸면 화면이 따라오게).

## 0. 작업 범위 (가장 중요)
- 새로 만들 파일 (모두 저장소 맨 위, 지금 index.html과 같은 위치. 폴더를 만들지 말 것):
  index.html (새 그래프 화면 — 이 파일 하나에 HTML·CSS·JS를 모두 넣을 것),
  graph-three.min.js (three.js 0.149.0, 전역 THREE를 쓰는 빌드. landing-three.min.js와 같은 파일을 복사해도 됨),

  graph-jetbrains-mono-latin-400-normal.woff2 / -500 / -600,
  graph-LICENSES.md (위 파일들의 출처와 라이선스)
  - 파일 이름을 전부 "graph"로 시작하게 하는 이유: 기존 파일과 겹치지 않고,

  - 라이브러리·폰트는 CDN이 아니라 위 파일로 불러와 (인터넷이 불안한 발표장에서도 같은 모양).
- 기존 파일에서 바꿀 것 (이것 하나만):
  기존 index.html의 이름을 index-legacy.html로 바꿔 보관한다 (되돌릴 수 있게).
- 절대 건드리지 말 것:
  landing.html과 landing-* 파일, list.html, dashboard.html, companies/ 폴더의 데이터,
  assets/ 폴더 (index-legacy.html이 계속 씀), 데이터를 만드는 스크립트.
- 작업 순서:
  1) 저장소 구조(index.html·list.html·dashboard.html 위치, companies/index.json의 항목 이름,
     그 JSON을 만드는 스크립트 위치)를 먼저 읽고 설명해줘.
  2) 아래 "4. 데이터"의 항목 이름이 실제 JSON과 다르면 임의로 맞추지 말고 먼저 알려줘.
  3) 작업 후 바꾼 파일 목록을 알려주고, 랜딩·목록·대시보드가 전과 똑같이 동작하는지 확인해줘.

## 1. 들어오고 나가는 동작
- 랜딩 규칙은 기존 index.html과 똑같이 유지:
  sessionStorage에 ubda_entered가 없고 주소에 ?…나 #…가 없으면 location.replace('landing.html').
  - location.href가 아니라 location.replace를 쓸 것 (뒤로 가기가 끝없이 되풀이되지 않게).
  - try/catch로 감쌀 것 (sessionStorage를 못 쓰는 환경에서는 랜딩 없이 그래프가 그대로 열려야 함).
  - 화면을 그리기 전에 판단할 것 (그래프가 잠깐 보였다가 넘어가는 깜빡임 방지).
- 기업으로 들어가기 (가장 중요 — 누르기 불편하면 안 됨):
  - 기업 점을 한 번 누르면 같은 탭에서 그 기업의 dashboard_path로 이동.
  - 기업 이름 라벨도 링크. 점을 정확히 맞추지 않아도 이름을 누르면 이동.
  - 기업 둘레의 작은 지표 점을 눌러도 같은 대시보드로 이동.
  - 점이 작게 보일 때도 화면에서 반지름 14px 안이면 잡히게 할 것.
  - 마우스를 올린 기업 위에는 실제 <a> 링크를 겹쳐 놓을 것
    (가운데 클릭·새 탭으로 열기·주소 미리보기가 평소처럼 되게. window.open은 쓰지 말 것).
  - 드래그해서 화면을 돌리다 손을 뗀 것은 클릭으로 치지 않을 것 (4px 넘게 움직였으면 클릭 아님).
- 산업·카테고리·CORE를 누르면 이동하지 않고, 카메라가 그 노드로 다가가며 오른쪽 패널이 열린다.
- 오른쪽 위 LIST 버튼은 list.html로 이동.
- 터치 화면: 기업 점을 탭하면 패널이 열리고 「대시보드 열기」 버튼으로 이동 (이름 라벨을 탭하면 바로 이동).

  이모지, 둥근 알약 버튼 남발.

## 4. 데이터 — companies/index.json을 읽어서 그린다
- 화면이 열릴 때 fetch('companies/index.json', {cache:'no-cache'}).
- 쓰는 항목:
  updated_at / industries.<키>.name · color /
  companies[]: slug, name, stock_code, industry, categories(배열), competitors(기업 이름 배열),
               dashboard_path, latest_year,
               kpis.revenue · operating_profit · net_income (원 단위),
               kpis.operating_margin_pct · revenue_growth_pct · debt_ratio_pct
- 그래프 구조:
  CORE 1개 → 산업(기업이 있는 산업만, 기업 수 많은 순) → 카테고리 → 기업 → 지표 6개.
  - 기업의 categories가 여러 개면 그 카테고리들에 모두 선을 잇는다.
  - competitors에 있는 이름이 목록 안의 기업이면 "경쟁" 선을 잇는다 (양쪽에서 겹치면 한 번만, 목록에 없는 이름은 무시).
  - 지표 6개: 매출액 · 영업이익 · 순이익 · 영업이익률 · 매출 증가율 · 부채비율.
- 표시 규칙:
  금액은 원 → 억원으로 반올림, 1조 이상이면 "97.1조", 아니면 "5,242억". 비율은 소수 첫째 자리 + "%".
  매출액이 0이거나 없으면 "–". 영업이익률과 매출 증가율이 둘 다 0이거나 없으면 둘 다 "–" (은행 업종 — list.html과 같은 방식).
  값을 지어내지 말 것. 없는 값은 "–".
- 기업 점 크기는 매출 규모에 따라 조금만 다르게 (log10 기준, 가장 큰 기업도 산업 점보다 작게).
- index.json을 못 읽었을 때 (파일을 직접 열었을 때 등):
  파일 안에 넣어 둔 스냅샷(작업 시점의 기업 목록을 한 줄에 한 기업씩 적은 문자열)으로 그리고,
  대시보드 링크는 사이트 전체 주소로 새 탭에서 연다. 왼쪽 아래 DATA에는 스냅샷 날짜를 표시.
- graph 항목(nodes·links)은 쓰지 않는다. JSON을 손으로 고치지 말 것.

## 5. 패널 · 툴팁 · 키보드
- 패널 (고른 노드에 따라):
  - CORE: 산업 목록과 기업 수.
  - 산업: 카테고리별로 기업 칩. 칩은 그 기업 대시보드로 가는 링크(↗ 표시).
  - 카테고리: 소속 기업 칩 + 상위 산업.
  - 기업: 종목코드 · 이름 · "산업 › 카테고리" · 크림색 「○○ 대시보드 열기」 버튼(맨 위) ·
    KPI 6줄(기준 연도 표시) · 연결(카테고리, 경쟁사 — 누르면 그 노드로 이동).
    기업이 선택되면 이 버튼에 포커스를 줘서 Enter로 바로 열리게.
- 툴팁 (마우스를 올리면 커서 옆에):
  기업 → 이름 / "종목코드 · 산업 / 카테고리" / "매출 ○ · 영업이익 ○ · 클릭하면 대시보드 ↗".
  산업 → 카테고리 수와 기업 수. 카테고리 → 소속 산업. 화면 오른쪽 끝에서는 커서 왼쪽에 뜨게.
- 키보드: ←→ 같은 부모의 이웃 노드 / ↑ 상위 / ↓ 하위 / ESC 처음 화면 / "/" 검색.

## 6. 그래프 구현 — three.js
- 배치(GRAPH): 직접 만든 3D 힘 시뮬레이션. 노드끼리 밀어내고(거리 제곱에 반비례) 선이 용수철처럼 당김.
  선 길이 기준: CORE–산업 62 / 산업–카테고리 20 / 카테고리–기업 11 / 경쟁 16(같은 산업)·40(다른 산업, 아주 약하게).
  지표 점은 시뮬레이션에 넣지 않고 기업 둘레 반지름 3.6~5 구면에 고르게 붙인다.
  세로로 살짝 납작하게(화면 비율에 맞게). 처음엔 가운데에서 퍼지며 자리를 잡는다.
- 배치(CLUSTER): 산업마다 하나의 공 모양으로 모으고(피보나치 구면 위에 산업 중심, 그 안에 소속 노드를 고르게),
  산업 사이에는 CORE 선과 경쟁 선만 길게 보이게. GRAPH와 부드럽게 오간다.
- 노드: THREE.Points + ShaderMaterial, 가산 혼합. 또렷한 원(가장자리만 살짝 부드럽게) + 옅은 빛번짐.
  CORE·산업·선택된 노드에는 가는 고리.
  크기: CORE 10 / 산업 6.5 / 카테고리 3 / 기업 3.1~5.6 / 지표 1.25. 화면에서 최소 1.6px.
- 선: THREE.LineSegments, 정점 색. CORE에서 나가는 선은 크림색 → 산업색으로 변하게.
  밝기: CORE–산업 0.30 / 나머지 트리 0.22 / 경쟁 0.20 / 지표 0.16.
- 산업마다 먼지 구름: 산업 소속 노드들의 중심 둘레에 작은 점 약 520개(모바일 240개)를 공 모양으로,
  아주 천천히 돌고 은은하게 반짝이게. 뉴런 다발처럼 보이는 것이 목표.
- 신호 입자: 작은 빛 약 130개가 선을 따라 CORE → 산업 → 기업 방향으로 흐른다.
  노드를 고르거나 올리면 그 노드와 연결된 선으로만 모인다.
- 심도: 초점(카메라가 보는 노드)보다 먼 노드·선·먼지는 최대 72%까지 어둡게.
- 강조 (옵시디언 방식): 노드에 마우스를 올리거나 고르면 그 노드와 직접 연결된 것만 밝게,
  나머지 노드는 13%, 선은 12%로 어둡게.
  연결 범위 — 산업: 그 산업 전체 / 카테고리: 소속 기업과 상위 산업 / 기업: 카테고리·산업·지표·경쟁사.
- 라벨: HTML 요소를 노드 오른쪽에 붙인다.
  CORE·산업은 항상, 카테고리는 카메라 거리 170 이하, 기업은 190 이하이거나 강조됐을 때, 지표는 그 기업을 고르거나 올렸을 때만.
  라벨끼리 겹치거나 범례·검색창·패널 자리에 들어가면 덜 중요한 쪽을 숨긴다
  (우선순위: 고른 노드 > CORE > 산업 > 기업 > 카테고리 > 지표, 이미 보이던 라벨을 조금 우대해 깜빡임 방지).
- 카메라: 직접 만든 궤도 조작. 드래그 회전(손을 떼면 관성으로 조금 더), 휠·두 손가락 확대,
  3.5초 동안 조작이 없으면 아주 천천히 자동 회전.
  노드를 고르면 그 노드로 부드럽게 다가간다 (거리: 산업 105~120 / 카테고리 80 / 기업 66).
  아무것도 고르지 않았으면 그래프 전체가 화면에 들어오는 거리로 맞춘다.
- 등장: 카메라가 멀리서 돌아 들어오고, CORE → 산업 → 카테고리 → 기업 → 지표 순서로 켜진다.
- prefers-reduced-motion이면 등장 연출·자동 회전·신호 입자·반짝임을 끈다.
- WebGL을 쓸 수 없으면 안내 문구를 보여 준다.
- devicePixelRatio는 최대 2. 탭이 숨겨지면 애니메이션을 멈출 것.

## 7. 완료 후 확인
python -m http.server 같은 정적 서버로 띄워서 확인해줘 (file://로 열면 fetch가 막혀 스냅샷으로 그려짐).
1) 사이트 주소를 그냥 열면 랜딩이 먼저 뜨고, 「기업 네트워크 보기」로 새 그래프 화면에 들어오는지
2) 왼쪽 아래 산업·기업 수와 DATA 날짜가 companies/index.json과 같은지
3) 기업 점·기업 이름·패널 칩을 한 번 눌러 같은 탭에서 dashboard_path로 이동하는지 (산업 서너 곳에서)
4) 대시보드에서 뒤로 가기를 누르면 랜딩이 아니라 그래프로 돌아오는지
5) LIST → 목록 → 3D 보기를 오가도 랜딩으로 돌아가지 않는지
6) 검색 → Enter → Enter로 대시보드까지 가는지, ←→↑↓와 ESC가 동작하는지
7) companies/index.json에 시험용 기업 하나(새 산업 포함)를 임시로 넣었을 때
   index.html을 고치지 않아도 그래프에 나타나는지 — 확인 후 시험용 항목은 되돌릴 것
8) 휴대폰 폭(390px)에서 가로로 넘치지 않는지, 콘솔 에러가 없는지, 외부로 나가는 요청이 없는지
9) index-legacy.html을 index.html로 되돌리면 예전 화면이 그대로 동작하는지 (되돌리기 확인)
끝나면 바꾼 파일 목록, 위 9개의 결과, 확인하지 못한 항목을 알려줘.
