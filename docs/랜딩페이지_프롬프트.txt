이 저장소(UBDA 경영분석 — 산업 → 카테고리 → 기업을 3D 네트워크로 탐색하는 정적 사이트) 앞에
"기업 경영 대시보드" 랜딩페이지를 붙여줘.
사이트 주소를 열면 랜딩페이지가 먼저 뜨고, 버튼을 누르면 지금의 3D 기업 네트워크(index.html)로 들어가는 구조야.
랜딩페이지는 어두운 우주 배경 위에서 파티클 한 무리가 스크롤에 따라 다섯 장면으로 모양을 바꾸는 스크롤형 페이지야.

## 0. 작업 범위 (가장 중요)
- 새로 만들 파일 (모두 저장소 맨 위, index.html과 같은 위치. 폴더를 만들지 말 것):
  landing.html (랜딩페이지 본체 — 이 파일만 직접 열어도 혼자 동작해야 함),
  landing-three.min.js (three.js 0.149.0), landing-d3.min.js (D3 v7), landing-topojson.min.js (topojson-client 3.1.0),
  landing-countries-110m.json (world-atlas 2.x의 110m TopoJSON),
  landing-Pretendard-Regular.subset.woff2 / -Medium / -ExtraBold, landing-barlow-semi-condensed-latin-500-normal.woff2 / -600,
  landing-LICENSES.md (위 파일들의 출처와 라이선스)
  - 파일 이름을 전부 "landing"으로 시작하게 하는 이유: 기존 파일과 겹치지 않고,
    GitHub 웹 업로드에서 폴더 구조가 풀려도 경로가 깨지지 않게 하려는 것.
  - 라이브러리·지도·폰트는 CDN이 아니라 위 파일로 불러와 (인터넷이 불안한 발표장에서도 같은 모양).
- 기존 파일에서 바꿀 것 (이것 하나만):
  index.html의 <head> 여는 태그 바로 다음 줄에 아래 스크립트를 넣는다.
    <script>
    try{
      if(!sessionStorage.getItem('ubda_entered') && !location.search && !location.hash){
        location.replace('landing.html');
      }
    }catch(e){}
    </script>
  - <head> 안 맨 위에 둘 것 (3D 화면이 잠깐 보였다가 넘어가는 깜빡임 방지).
  - location.href가 아니라 location.replace를 쓸 것 (뒤로 가기가 끝없이 되풀이되지 않게).
  - try/catch를 지우지 말 것 (sessionStorage를 못 쓰는 환경에서는 랜딩 없이 기존 사이트가 그대로 열려야 함).
- 절대 건드리지 말 것:
  index.html의 나머지 부분, list.html, 3D 네트워크 코드, 기업 대시보드 페이지, 데이터 파일, 기존 CSS.
- 작업 순서:
  1) 저장소 구조(index.html·list.html이 어디 있는지, 기업 페이지로 가는 주소 형식)를 먼저 읽고 설명해줘.
  2) 기업 페이지나 특정 화면으로 바로 가는 주소가 쿼리(?…)나 해시(#…)가 아닌 다른 방식이면,
     그 주소들이 랜딩으로 끌려가지 않는지 확인하고 필요하면 위 조건을 알려줘 (임의로 바꾸지 말고 먼저 물어볼 것).
  3) 작업 후 바꾼 파일 목록을 알려주고, 기존 화면이 전과 똑같이 동작하는지 확인해줘.

## 1. 들어가는 동작
- 랜딩의 「기업 네트워크 보기」 버튼(상단 오른쪽, 01 섹션, 05 섹션) 또는 Enter 키:
  sessionStorage에 ubda_entered = "1"을 저장하고 index.html로 이동.
  이동 전 약 1초 동안 파티클이 바깥으로 퍼지며 화면이 밝아지는 전환 효과.
- 05 섹션의 「목록으로 보기」 링크: 같은 값을 저장하고 list.html로 이동.
- 결과적으로:
  - 사이트 주소를 처음 열면 랜딩이 뜬다.
  - 한 번 들어온 탭에서는 목록 ↔ 3D 보기를 오가도 랜딩이 다시 뜨지 않는다.
  - 새 탭·새 창에서는 다시 랜딩부터 시작한다.
  - 주소에 ?…나 #…가 붙어 있으면 랜딩을 건너뛴다 (공유한 링크 보호).
- 주소에 ?preview가 붙으면 버튼이 실제로 이동하지 않고 안내 문구만 띄운다 (미리보기용).

## 2. 디자인 토큰 — "조용한 우주"
- 분위기: 거의 검은 배경, 흰색·회색 글자, 강조색은 시안 하나. 화려함은 뒤의 파티클에만 두고 글은 최소한으로.
- 폰트: 한글 Pretendard (400·500, 큰 제목만 800), 영문 라벨·숫자 Barlow Semi Condensed (500·600).
- 색: 배경 #030406 / 글자 #F2F3F5 / 보조 #8B9099 / 흐린 글자 #5A5F68 / 강조 시안 #4FC3F7.
- 큰 제목은 두 줄: 첫 줄 흰색(굵기 500), 둘째 줄 회색 #7F848D(굵기 400). 크기 clamp(38px, 5.1vw, 76px), 자간 -0.042em.
- 버튼: 흰색(#F4F5F7) 알약. 그라데이션·두꺼운 그림자 대신 1px 흰 테두리 + 5px 아주 옅은 바깥 고리. 올리면 안의 점이 오른쪽으로 3px 이동.
- 스크롤바는 가늘게(8px, 반투명 흰색).
- 하지 말 것 (촌스러워 보이는 원인):
  유리 느낌 카드·박스로 글을 감싸기, 글 뒤에 파티클을 가리는 진한 배경, 여러 색을 같은 비중으로 쓰기,
  긴 설명문 (섹션당 제목 2줄 + 설명 2줄 이내), 숫자 위로 파티클이 지나가 글이 묻히는 배치.
- 글 가독성: 글 뒤에는 테두리 없는 아주 옅은 어둠(radial-gradient, 가운데 rgba(3,4,8,.55) → 바깥 투명)만 깐다.

## 3. 레이아웃
- 화면 높이를 꽉 채우는 섹션 5개가 세로로 이어지는 스크롤 페이지. 파티클 캔버스는 화면에 고정(position:fixed).
- 상단 고정 바: 왼쪽 로고(궤도 모양 SVG) + "UBDA 경영분석", 가운데 섹션 링크(소개·구조·데이터·네트워크),
  오른쪽 흰색 알약 버튼 「기업 네트워크」.
- 오른쪽 가장자리 세로 목차: 01 INTRO / 02 STRUCTURE / 03 PIPELINE / 04 NETWORK / 05 ENTER.
  현재 섹션만 밝게, 누르면 그 섹션으로 이동.
- 모바일(폭 390px)에서 가로로 넘치지 않을 것. 목차·섹션 링크는 좁은 화면에서 숨김.
- 글 등장: 섹션이 화면에 30% 들어오면 한 번만 실행.
  제목은 한 줄씩 아래에서 올라오고(가려진 상자 안에서 translateY 112% → 0, 1.05초, 둘째 줄은 0.09초 늦게),
  나머지 요소(라벨·설명·버튼·정보 줄·단계·숫자)는 0.09초 간격으로 12px 아래에서 떠오름.
  작은 라벨 앞의 선은 0에서 22px로 그어짐. prefers-reduced-motion이면 이 효과를 모두 끔.

## 5. 파티클(우주) 구현 — three.js
- 파티클 수: 데스크톱 52,000개, 모바일 18,000개 (많고 작게 — 고운 입자). THREE.Points + ShaderMaterial, 가산 혼합(AdditiveBlending).
- 장면 전환은 GPU에서: 각 파티클이 "지금 장면 위치"와 "다음 장면 위치"를 속성으로 갖고,
  스크롤 진행도(uMix)로 섞는다. 장면 쌍이 바뀔 때만 속성을 다시 넣는다 (매 프레임 CPU 계산 금지).
  - 파티클마다 출발을 조금씩 늦추고, 바뀌는 동안 소용돌이치듯 살짝 돌면서 한 번 흩어졌다 다시 모이게.
  - 섹션 가운데 구간에서는 모양이 고정되고(uMix를 smoothstep(0.15, 0.85)로), 섹션 사이에서만 변한다.
- 별 모양: 또렷한 중심(exp(-r²·15)) + 아주 옅은 빛번짐. 3.5%는 크고 아주 옅은 빛안개, 1.5%는 밝은 큰 별, 나머지는 아주 작게.
  밝은 큰 별에만 가는 십자 빛줄기를 아주 옅게 (초점에서 벗어난 별에는 없음). 빛안개가 뿌옇게 뭉치면 안 됨.
- 초점 번짐: 카메라 초점면에서 먼 파티클은 크고 흐리게 (구·지구의 뒷면이 자연스럽게 흐려짐).
- 은하 모양: 부푼 중심(13%) + 나선팔 2개(가는 줄기·넓게 번지는 먼지·별 무리) + 옅은 원반 + 헤일로.
  가는 리본처럼 보이면 안 됨.
- 배경: 화면 전체 셰이더로 그리는 성운 (겹겹이 일그러뜨린 노이즈, 남색·보라·청록, 어두운 먼지 띠, 가장자리 어둡게).
  스크롤하면 천천히 흘러가고 장면마다 농도와 색 기울기가 조금씩 바뀜. 동그란 빛 덩어리 스프라이트는 쓰지 말 것.
- 배경 별: 데스크톱 약 5,200개(모바일 2,200개), 절반은 비스듬한 은하수 띠에 모으고 별마다 색온도·밝기가 다르게.
- 움직임: 파티클이 물결처럼 함께 일렁임, 각자 반짝임, 카메라가 숨 쉬듯 미세하게 움직임, 마우스에 살짝 반응.
- 성운은 형태를 받쳐 주는 정도로만 옅게 (파티클보다 눈에 띄면 안 됨).
- 전체 밝기는 차분하게. 흰색으로 타 버리지 않게 하고, 글자를 가리지 않을 것.
- prefers-reduced-motion이면 반짝임·일렁임·흩어짐을 끄고 장면만 바뀌게.
- WebGL을 쓸 수 없으면 파티클 없이 글과 버튼만으로도 읽히고 들어갈 수 있어야 함.
- devicePixelRatio는 최대 2. 탭이 숨겨지면 애니메이션을 멈출 것.

## 6. 완료 후 확인
1) 사이트 주소를 그냥 열면 랜딩이 먼저 뜨는지
2) 「기업 네트워크 보기」와 Enter 키로 3D 네트워크에 들어가는지, 들어간 화면이 전과 똑같이 동작하는지
3) 목록 보기 → 3D 보기를 오가도 랜딩으로 돌아가지 않는지
4) 뒤로 가기를 눌러도 화면이 끝없이 되풀이되지 않는지
5) 주소에 ?…나 #…가 붙은 링크, 그리고 기업 페이지 주소가 랜딩을 건너뛰고 바로 열리는지
6) 새 탭에서 열면 다시 랜딩부터 시작하는지
7) 휴대폰 폭(390px)에서 가로로 넘치지 않는지, 콘솔 에러가 없는지
8) index.html의 스크립트를 지우면 랜딩 없이 예전처럼 동작하는지 (되돌리기 확인)
